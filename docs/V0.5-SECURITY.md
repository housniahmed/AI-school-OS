# V0.5 — Security & Observability

## Security controls added

- HTTP security headers with Helmet.
- Trusted-proxy configuration is explicit through `TRUST_PROXY`.
- Distributed API rate limiting is backed by Redis.
- Login is protected by a stricter rate limit.
- Request IDs are generated or propagated through `X-Request-ID`.
- Structured request logs contain method, path, status, latency and tenant/user context without request bodies or authorization headers.
- JWT production validation rejects insecure/default secrets.
- Tenant isolation and permission checks remain enforced at the API boundary.

## Availability contract

Redis is now a required runtime dependency for rate limiting. Readiness therefore reports both PostgreSQL and Redis. A deployment should not receive traffic while either dependency is unavailable.

## Operational principle

Security mechanisms are designed to fail closed where access control is concerned. Tests must exercise the real middleware stack and must not bypass it merely to simplify fixtures.
